## 实际工作流

| 环节       | 已实现                                                                                   | 使用边界                                                                        |
| ---------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 卡包管理   | 新建、复制、删除卡片；多卡包；卡号起点和批量补号；系列映射；自动保存；工程 JSON 备份恢复 | 128–268435455 的作者卡号范围；仅检查当前卡包重号，不分配全球区间                |
| 输入       | 原生工程、两种制卡器 JSON、已知游戏王模板的 MSE-SET；中间图上传；中英日卡文              | 不保留与 CDB/继续编辑无关的源工具元数据，不保证任意第三方模板通用               |
| 卡面       | 怪兽、魔陷、额外、灵摆、连接；完整卡模、字体；独立左右刻度；连接箭头                     | 缺图时输出明显占位图；保留主要内容，不复刻各源工具的所有排版和稀有度            |
| 无模型脚本 | 下表动作与有限条件、费用、次数、发动区域、素材手续；即时生成和基础验证                   | 多块积木表示多个独立效果，不等于同一次发动中的任意动作序列                      |
| 文本匹配   | 英文、中文常用完整句式；少量日文；逐卡/批量生成候选；保留未知文本                        | 不推断任意裁定；部分识别仍标为待复核，作者明确核对后才能解除                    |
| BYOK       | OpenAI 兼容 Chat Completions；参考卡检索/脚本；完整 Lua、字符串与说明；格式错误一次修复  | 不是完整远端 workflow；不自动编排文件工具或生成决斗测试；无真实用户端点调用验证 |
| 脚本编辑   | 整卡 Lua 模式与 CDB 提示字符串；语法、入口和卡号检查                                     | 积木模式和整卡模式由用户切换；不从任意 Lua 反向还原积木                         |
| 输出       | SQLite CDB、697×1015 PNG、Lua、系列名称、导出报告与导入说明                              | 有结构/编号/语法错误不能导出；有待核对警告需明确选择草稿包                      |
| 存储       | 浏览器 IndexedDB；可选服务器 JSON；工程结构校验                                          | 服务端为私人工作室共享空间，没有多用户认证与隔离                                |

修改卡文或效果会重新标记待核对。备份保留积木和手工脚本；模型不会在后台替换这些内容。用户必须点击应用模型结果才切换为完整 Lua。

## 首批模板的真实范围

| 动作               | 当前参数与语义                                                           |
| ------------------ | ------------------------------------------------------------------------ |
| 卡组检索           | 从自己卡组选择固定数量加入手卡并公开；系列、卡种、种族、属性、等级等筛选 |
| 墓地回收           | 单对象，回持有者手卡                                                     |
| 抽卡               | 指定玩家，固定数量                                                       |
| 卡组选送墓地       | 从自己卡组选固定数量，以效果送墓；不等于卡组顶送墓                       |
| 破坏 / 回手 / 除外 | 单对象；合法区域和玩家；除外为表侧                                       |
| 墓地苏生           | 单对象，特召到自己场上，检查可特召性与可用区域                           |
| 选择特召           | 处理时从自己手卡/墓地选择单体，非发动时取对象                            |
| 手卡特召手续       | 自己无怪兽或仅对方有怪兽的预设；非连锁手续                               |
| 临时攻守增减       | 场上单体表侧怪兽，固定增减到回合结束，守备力变化检查是否有守备力         |

动作之外支持：魔陷发动、起动、快速、召唤/特召/反转/送墓事件；场上/手卡/墓地/除外发动区域；丢手、手卡送墓、自身送墓/除外、支付 LP；单卡/卡名/共用计数；基本灵摆配置。计数键在卡包内统一分配，避免把连续卡号简单作为 `id+1` 使用；手工 Lua 的计数由作者维护。

事件入口按「场合 / If」与 DELAY 处理；「时 / When…you can」不自动匹配，请用完整 Lua。召唤手续包括 1 调整与非调整的基本同调、固定等级/数量超量、效果怪兽连接和 2–4 张指定卡号融合。仪式魔法、复杂素材、特殊替代手续、任意连续处理、无效效果、持续对象关系、多体同时特召等走完整 Lua / BYOK。生成器会报错或提示边界，不静默降级。

## 部署依赖

- 前端 React / TypeScript / Vite，服务端 Express / Node；库版本通过 package-lock 管理。
- CDB 在浏览器 SQL.js 中按 YGOPro 两表布局建立，64 位系列码使用整数文本绑定避免 JavaScript 精度损失；提示字符串固定 16 槽。
- `yugioh-card` 为 npm 运行依赖；卡模/字体共 82 个必要上游文件约 42.2 MiB，随项目纳入 `public/card-assets`，保留来源及 SHA-256 清单。完整 checkout 可离线校验，缺文件时按清单恢复。
- 参考文本、Lua、内核接口清单部署到 `.data/references`。同步命令读取当时最新上游并记录来源；不在服务运行时读取兄弟仓库。
- MSE 仅作为 ZIP/文本格式解析；不部署 MSE 可执行程序。测试用 Koishi WASM 内核和测试封装是本项目开发依赖。

## 验证证据与限度

- 上传的两个 JSON 分别导入 1 张；ANSD.mse-set 导入 22 张。24 张卡均在真实浏览器完成卡图渲染，保留中间图，MSE 英文正文与中文注释分开，重复卡名不合并。
- 浏览器验证了效果怪兽、魔法、连接、超量和通常灵摆等卡面，独立左右刻度、连接箭头以及并行绘图。三卡示例完整 ZIP 实际下载后，重新读取 CDB 并核对卡号、类型、系列码与对应 PNG/Lua。
- 单元/集成测试覆盖编号、计数、费用、材料、未知句式保留、中文示例、真实文件适配、64 位 setcode、脚本语法/入口、项目存储、参考检索、BYOK 响应与来源校验。
- Koishi 内核测试加载 16 种生成配置，并实际结算检索及同名次数阻断、抽卡、对象破坏、苏生、手卡特召、墓地除外自身抽卡。
- 尚未对每一模板参数组合、官方 YGOPro 原生客户端、真实 BYOK 服务、Docker 镜像执行完整验收。内核测试用的是项目 npm 中 Koishi WASM 版本，不能推断所有官方版本都已通过；作者仍需本地试卡。

运行 `npm test` 和 `npm run build`。内核/真实参考测试依赖已同步缓存；样例文件回归需要 `DAY_LILIES_IMPORT_FIXTURES` 指向用户样例目录，文件本身不会打入仓库。服务端 BYOK 测试使用模拟端点，不消耗用户额度。
