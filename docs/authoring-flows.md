# 文本匹配 手动组装与 BYOK 的衔接

三种入口共用一份效果草稿。文本匹配和 BYOK 帮助填写草稿，手动模式直接编辑同一份配置，再由生成器输出 Lua 与对应的 CDB 提示字符串。超出积木能力的卡片可以进入自定义 Lua 模式。

效果草稿的字段和组合语义见[效果积木体系](effect-block-system.md)，模板范围见[常用效果模板](common-effect-templates.md)。本流程不要求从任意 Lua 反向还原积木。

## 三种入口的分工

| 入口 | 用户提供 | 应用完成 | 遇到无法确定的部分 |
| --- | --- | --- | --- |
| 文本匹配 | 主效果文本、卡片种类、已有卡号和系列资料 | 分段，匹配模板，提取参数，显示覆盖的原文，形成草稿 | 保留未匹配片段；缺参数列出待填项；歧义给出具体选择 |
| 手动组装 | 选择常用模板或高级积木，填写规则参数 | 用相同草稿表达效果，限制不合法的组合，生成代码 | 可以保存未完成草稿，转 BYOK 或自定义 Lua |
| BYOK | 主文本、修改要求、现有草稿及用户选择的模型 | 优先填充或修改模板；必要时检索脚本与内核，编写自定义 Lua | 说明未确定的规则或未完成部分，保留用户修改和可比较的结果 |

三个入口共享卡号、系列映射、效果编号和提示字符串分配，避免分别生成三套互不兼容的卡片数据。API Key 不属于卡片工程或下载产物。

## 文本匹配流程

1. **确定上下文。** 先知道卡种、主语言、目标内核和已有系列映射。英文 PSCT 是输入格式，不自动意味着采用 TCG 裁定；执行依据仍是所选目标。
2. **轻量归一化。** 统一可识别的全半角、编号与术语变体，剥离仅供制卡排版的标签。保留有规则意义的标点、连接词、否定、数量和原始句段。
3. **拆出编号效果与共用限制。** 灵摆效果和怪兽效果分开；召唤手续、卡名次数和覆盖全回合的限制不能只归到最近的一句话。
4. **匹配模板结构。** 同时比对事件、卡种、区域、选择时机、动作、数量及限制，不能只用“加入手牌”之类关键词决定整段已实现。
5. **填充参数和引用。** 系列名称关联 setcode，指定卡名关联卡号；“这张卡”“那张卡”“以此法处理的卡”关联相应记录。未知引用留待填写，不自行分配系列代码。
6. **显示结果。** 用户看到模板、已填参数、对应原文和剩余片段，并能直接进入手动编辑。

英文先支持常见 PSCT 句式。冒号和分号有助于区分发动条件、发动时事项和处理；发动时事项包括代价与取对象，不能把分号前全部当作代价。魔法陷阱发动也不能仅凭有没有冒号判定是否进入连锁。[官方 PSCT 结构说明][psct]

中文以官方简中与常见民间译法的术语映射扩展覆盖，日文以常见固定句式与对应官方脚本扩展覆盖。未知词句不等于内核不支持，也不应因为语言不同而强制经过英文翻译。

## 匹配覆盖与工作状态

| 情况 | 应如何呈现 | 后续动作 |
| --- | --- | --- |
| 模板和参数均明确 | 显示已匹配的原文、模板和参数 | 可编辑并生成 |
| 已匹配但缺参数 | 例如系列名已识别，setcode 尚未填写 | 补参数或关联已有系列 |
| 有多个合理解释 | 例如发动时取对象或处理时选择尚不明确 | 让作者选择具体语义，或交给 BYOK 辅助解释 |
| 部分句子未实现 | 显示完整剩余片段及原因 | 补积木、改写设计、BYOK 或自定义 Lua |
| 原文已经修改 | 相关效果标记待复核 | 比较新旧匹配结果，再接受修改 |
| 使用自定义 Lua | 明确当前脚本由用户或 BYOK 维护 | 继续导出、检查和编辑，不承诺恢复为积木 |

覆盖状态与检查状态分别保存。“文本已全部映射”“脚本可加载”“行为测试已执行”“作者已实机验收”表达不同事实，不能用一个通过标记代替。

允许保存未完成工程。若用户选择下载部分实现的草稿，界面应明确列出未完成部分；CDB 中保留用户选择导出的完整卡文，不能为了迁就脚本覆盖范围而删除句子。常规完成状态为“已生成，待作者实机验收”。

## 手动组装流程

普通模式从常用效果模板开始，只显示变化参数。例如系列检索显示系列、卡种、数量、附加筛选、条件、代价和次数；默认的提示与处理骨架由模板提供。

高级模式允许编辑时机、条件、代价、选择、动作、结果引用与后续限制。编辑器应把取对象、处理时选择和持续影响范围分开命名，避免要求用户理解底层同名 target 回调的不同职责。

模板固定部分可以展开查看，但不必把每个底层 API 都作为可拖拽节点。选择组、实际处理结果、共享次数组等使用可读名称，例如“①选择的对象”“①实际加入手牌的卡”“①②共用次数”。

可以从积木提出卡文建议，但不自动重写作者的原文或所有翻译。作者接受文本后，再更新草稿与主文本的对应关系。

## BYOK 流程

BYOK 配置包括兼容端点、模型和 Key。模型能力与执行工具分别适配；只发送一份提示词不能代替检索、生成和运行 workflow 的过程。

模型需要的最小上下文是当前主文本、卡种与卡号、系列映射、目标能力、已有草稿、未实现片段，以及本次实际检索到的参考代码。已被作者确认或手动修改的字段应保留其状态。

优先让模型使用已支持模板并填写相同的草稿，这样结果仍能在手动模式编辑。模板之外的效果按 workflow 的思路查找相似卡、核对 API、生成 Lua 和对应提示字符串，并在可用时进行加载检查或用户选择的行为测试。

初版采用整卡自定义脚本出口：一旦作者接受自由 Lua，整张卡进入自定义脚本模式。以后可以增加受约束的局部扩展点，但首版不混合任意代码片段和自动生成函数，避免它们共同修改同一效果、次数代码或提示索引。

模型输出的是可比较、可继续编辑的结果。模型不能凭文字系列名创造未经作者确认的 setcode，也不能在模板未覆盖时静默省略自肃、代价或后续效果。

## 修改后的衔接规则

| 修改来源 | 需要更新的内容 | 保留的内容 |
| --- | --- | --- |
| 主效果文本变化 | 相关效果待复核，重新匹配后显示差异 | 已有手工参数和自定义脚本，不自动覆盖 |
| 参考翻译变化 | 更新参考显示 | 主规则草稿与 Lua，除非作者改选规则依据 |
| 积木参数变化 | 派生 Lua 和提示字符串待重新生成 | 原卡文；可另给修改建议 |
| 作者直接编辑 Lua | 转入整卡自定义脚本模式 | CDB 数据、卡图与已有草稿快照，后者不再被视为当前脚本的完整描述 |
| 卡号或系列代码变化 | 重新检查脚本、提示、文件名及跨卡引用 | 自定义 Lua 不做盲目的全局文本替换，改由作者或 BYOK 辅助修订 |
| 上游资料更新 | 新任务使用新资料，受影响模板进行维护检查 | 现有卡片脚本不自动改写 |

重新选择模板生成可以产生一份新结果供比较，不能直接覆盖当前自定义 Lua。应用保存这些工作状态是为了继续编辑，无须恢复原制卡器的全部元数据。

## 系列专用增援示例

以下为设计示例，并非新增实际卡片。假定作者创建通常魔法“星庭的征集”，英文卡名为 Starcourt Muster，系列译名 Starcourt 对应“星庭”。卡号和系列 setcode 由作者填写。

英文主文：

> Add 1 “Starcourt” monster from your Deck to your hand. You can only activate 1 “Starcourt Muster” per turn.

三种入口最终应得到同一组规则：

| 项目 | 配置 |
| --- | --- |
| 发动 | 通常魔法发动，常规发动时机 |
| 条件与代价 | 没有文本额外指定的条件或代价 |
| 检索范围 | 自己卡组中的星庭系列怪兽，且能够加入手牌 |
| 选择 | 处理时选择 1 张，不取对象 |
| 动作 | 加入自己手牌并向对手公开 |
| 次数 | 每回合同名卡只能发动 1 张；不能替换为“这个效果只能使用一次” |
| 依赖 | 作者卡号、系列 setcode、卡种、提示与动作类别 |

文本匹配识别系列检索模板，并将缺失的 setcode 留作待填项。手动模式直接选择相同模板。BYOK 解析文本后填写相同草稿；检索主体可参考[增援脚本][rota]，发动次数单独参考[强欲而贪欲之壶的计次设置][oath]和[次数常量][count]，不继承参考卡的其他效果。

生成后，CDB 记录、pics 下的整卡图片以及 script 下的 c卡号.lua 使用同一个作者卡号。作者在本地验证检索范围、同名卡发动次数和与其他卡的交互。

### 未完成片段示例

若作者又加入“这个回合，自己不是龙族怪兽不能特殊召唤”，应用应判断当前模板是否支持对应时间范围的召唤限制。“这个回合”涉及此前行为时，也不能直接替换为“处理后直到回合结束”。

若该限制尚未被支持，检索部分可以完成，但整句限制应标为未实现。作者可以补充适合的限制模块、改写设计、交给 BYOK 或切换自定义 Lua；不能只因为找到检索模板就显示全卡已完成。这里反映模板覆盖范围，不表示内核没有相应能力。

## 更新与验收

同一次生成、检查与修复使用一致的目标资料；新的任务可采用更新后的上游。内部记录来源提交或构建标识，便于排查，不要求作者管理版本，也不把这些资料写进 CDB。

生成器基础检查包括卡号和文件对应关系、必要参数、引用、提示字符串及目标能力。可用时执行脚本加载检查；workflow 的红字检查主要让卡片进入卡组并推进，不能代替作者的实机验收。模板维护者为共用模板保留代表性检查，作者按自己的卡片测试实际效果。
