# 多语言与效果拼图扩展

更新日期：2026-10-17。本文记录本次实现范围，替代首版文档中「11 个模板」「复合效果只能用完整 Lua」等旧限制。常量数量表示可检索的接口数量，不代表已验证同样数量的独立效果配方，也不是对全部 OCGCORE 脚本覆盖率的统计。

## 界面语言与卡面语言

界面支持简体中文、英语、日语，覆盖主工作台、设置、导入导出面板、卡片编辑、拼图、BYOK 和应用诊断。界面语言保存在浏览器 `day-lilies:ui-language`，不进入工程卡片数据。存储不可用时仍可在当前页面切换。

每张卡的 `language` 仍是独立的卡面设置，支持简体、繁体、英语、日语；它决定卡面字体、属性图标、魔陷标签、种族／卡种标签以及生成的灵摆分段标签。卡名、正文、灵摆正文、备注、系列名称、效果提示和自定义 Lua 均保持作者输入。旧工程不需要迁移，备份继续保留每张卡的语言。

## 普通与复合积木

工具箱支持按名称／说明搜索和分组浏览，合计 33 个入口：原来的 11 个模板、19 个新处理、融合／仪式召唤、复合效果和高级效果。

| 处理族 | 已提供 |
| --- | --- |
| 手牌与卡组 | 检索、回收、回手、抽卡、从卡组选送墓地、卡组顶送墓、回卡组（洗牌／顶／底）、丢弃手牌 |
| 场面与墓地 | 破坏、送墓、表侧除外、墓地苏生、选择特召、手牌特召手续、表示形式、控制权、装备自身、盖放魔陷 |
| 战斗与数值 | 临时攻守、效果伤害、回复基本分、宣言并改变种族／属性 |
| 连锁 | 发动无效、连锁效果无效、场上卡片效果无效；无效后破坏可组合前步卡组 |
| 资源 | 增减指示物、叠放超量素材、取除素材；指示物数量与选卡张数独立 |

每个顶层积木仍代表一个效果。要在同一次发动中执行多个动作，应添加「复合效果」，在其内部安排 1–16 个步骤，而不是添加多个「卡的发动」。

每步可设置：

- 选择方式：发动时取对象、处理时选择、全部符合条件的卡、自身、前一步实际处理的卡组、指定对象组或指定较早步骤的结果。同一次发动可以配置多组对象，每组有独立名称、数量、区域与筛选。
- 对象组默认不能重叠；只有两组都明确允许时才可共享卡。发动前检查联合可行性，逐步选卡时保留后续组的可选解。组引用使用稳定内部 ID；复制效果会同步重建引用，重排和改名不改变指向，删除被引用步骤会产生诊断。
- 对象组按每条连锁独立保存，同一效果在一条连锁中发动多次也不会相互覆盖。原始对象按连锁关联判断是否仍有效；引用对象组的后续步骤还会检查该步骤自己的区域、控制者和筛选。单组可接受其他卡的改取对象；多组遭到外部整体改取对象时不猜测新卡归属，只处理原组中仍有关联的卡，特殊改取对象规则需自定义回调。
- 执行条件：总是、仅前步成功、仅前步失败；另可设为玩家选择是否执行。成功以实际处理结果判断，移动动作检查实际到达区域。
- 时序：前步之后处理（`BreakEffect`）或不分隔处理。与成功依赖分别配置；这不自动完成任何卡文的连接词裁定，也不把任意两个动作变成原子化的同时处理。
- 筛选：系列、指定卡号、种类、种族、属性、等级／阶级／连接值、攻守范围、表侧、调整、额外怪兽、同名排除；高级谓词可组合额外规则。

新增入口包括连锁响应、自身破坏／除外／回手／回卡组、战斗破坏、伤害、攻击宣言、准备／结束阶段及场上召唤／特召事件。新增费用包括解放自身、解放自己怪兽、墓地除外、取除素材、移除指示物。费用与效果处理使用各自原因和可支付性检查。

## 召唤手续与召唤效果

卡片资料中的「额外召唤手续」用于定义这张怪兽需要什么素材：

- 同调：1–3 只调整，分别设置调整与非调整筛选、总素材数量范围。
- 超量：素材等级、数量范围及筛选；可选叠放在指定表侧超量怪兽之上的替代路线。
- 连接：素材数量范围与筛选，连接值仍取卡片本身的 LINK 值。
- 素材筛选支持效果／非效果怪兽，非效果怪兽包含不具有效果的额外怪兽，不等同于通常怪兽。
- 融合：多个卡号／筛选素材槽，每槽有数量；支持至多一个可变数量槽，合计 2–8 张，并可设置是否允许融合素材替代。

「融合／仪式召唤」积木配置通过效果进行的召唤：选择可召唤怪兽、素材筛选与手牌／场上／墓地区域。墓地素材的处理明确为除外。仪式可设置等级恰好／至少满足、原本等级／当前等级／固定数值，以及从手牌或手牌与墓地选择仪式怪兽。次数、发动入口和费用沿用普通积木配置。

融合／仪式召唤也可以插入复合效果的任意步骤，沿用成功／失败分支、任意执行和步骤间时点设置。后续步骤的「实际结果」以及延迟追踪只记录实际召唤成功的怪兽，不会把素材当成召唤结果。独立召唤积木也支持延迟追踪。发动与结算分别检查召唤合法性；条件性步骤在轮到执行时检查。

普通「选择特殊召唤／苏生」支持每次同时特殊召唤 1–5 只怪兽，指定来源、筛选和表示形式。默认不固定表侧攻击或守备，结算时选择。取对象／处理时选择按配置数量检查发动条件；引用已有对象组或前步结果时，数量是上限。处理时重新检查空位、合法卡与一次特召数量限制，只保留实际成功组。对象／引用组遇到空位减少时可选择能容纳的子组；若仍需同时召唤多只却受到一次只能特召一只的限制，整步不处理，不擅自改为召唤一只。「全部符合条件」保持全组语义（最多 5 只），无法全组合法出场时整步不处理。普通批量步骤不包含从额外卡组召唤，额外怪兽的正规召唤仍使用对应手续或融合步骤。

融合怪兽的素材槽下可启用「接触融合手续」。它复用素材槽，配置自己／对方／双方素材、手牌／怪兽区域／墓地来源、作为费用洗回卡组或额外卡组／除外／送墓／解放，以及场上素材是否必须表侧。使用对方素材时限于表侧怪兽区域；解放来源不含墓地。可以限制从额外卡组只能通过接触手续、接触手续或融合召唤出场，也可不添加额外限制；正规出场后的苏生限制仍由内核执行。接触手续本身不入连锁，是规则特殊召唤，不视为融合召唤，也不允许融合素材代用。上方融合代用开关仅影响通常融合召唤。

这些配置调用 [YGOPRO 官方 procedure.lua](https://github.com/Fluorohydride/ygopro-scripts/blob/master/procedure.lua) 的同调、超量、连接、融合与仪式辅助函数，属于通用功能，不标作 KoishiPRO 专属。召唤手续定义和实际召唤处理是两个不同位置的配置；配置融合怪兽的素材不会自动替它生成一张融合魔法。

## 跨时点追踪

在普通或复合效果下添加「延迟追踪」，每个效果最多 8 项。来源可以是指定步骤，或配置中的最后一步；只记录该步实际处理成功的卡。可设本回合、下回合或下个符合玩家的准备／结束阶段，届时回手、回卡组、破坏、除外、送墓，或返回暂时除外的卡。

可以选择不入连锁的阶段处理或必发的阶段诱发效果、仍有效的卡分别处理或要求原组全部有效，以及离开追踪区域后是否失效。暂时除外返回仅适用于从场上除外的步骤，生成器添加 `REASON_TEMPORARY` 并调用 `Duel.ReturnToField`；它不算特殊召唤。追踪按每次结算分别建立，不会被同卡下一次发动覆盖。预定阶段被跳过不会自动补发，追踪会按所设期限结束。

例如，复合效果可以「取自己怪兽为对象并除外 → 抽卡」，再将延迟追踪的来源指定为第一步，设置本回合结束阶段返回。也可先定义 A、B 两组对象，处理 A 后抽卡，再通过「指定对象组」继续处理 B，无需手写卡组存储代码。

## 高级效果与持续规则

「高级效果配置」允许与普通积木共存，设置 Effect 类型、代码／事件、区域、双方适用范围、属性、分类、值、重置条件及次数。条件、费用、对象、处理、数值函数的回调及其参数均可编辑；作者只填写函数体，编译器负责命名和注册。

21 个起步预设覆盖战斗／效果破坏抗性、效果对象／攻击对象保护、不受对方效果影响、直接攻击、贯穿、额外攻击、不能攻击、攻守光环、等级／属性／种族变化、视为调整、不能特召、对方不能发动魔法、手牌上限和三种 Koishi 连接箭头操作。预设参数全部可见、可编辑；选择预设会替换当前高级配置，避免残留上一个预设的回调。

474 个脚本常量按效果、事件、类型、属性、分类、重置、区域等组织，另列 12 个 Koishi 扩展。每项保留来源。目录随项目部署，运行时不读取相邻仓库或联网；维护者同步参考资料后可运行 `node scripts/sync-capabilities.mjs` 重新生成。

## KoishiPRO 边界

本次基于参考内核的明确扩展定义，并对照 2026-10-17 读取的 [Fluorohydride 上游 effect.h](https://github.com/Fluorohydride/ygopro-core/blob/master/effect.h)。下列 12 项位于 [Koishi 分支扩展区](https://github.com/purerosefallen/ygopro-core/blob/ed031ac3e8882edea59defa71d11935e0a1b83dd/effect.h#L132-L144)，在所核对上游文件中没有相应定义：

| 扩展 | 含义 |
| --- | --- |
| `CHANGE / ADD / REMOVE_LINK_MARKER_KOISHI` | 修改连接箭头 |
| `CANNOT_LOSE_KOISHI` | 败北规则扩展；具体败北条件需单独验证 |
| `EXTRA_TOMAIN_KOISHI` | 额外卡组特殊召唤区域扩展 |
| `OVERLAY_REMOVE_COST_CHANGE_KOISHI` | 取除素材的最小费用调整 |
| `ADD / REMOVE / CHANGE_SUMMON_TYPE_KOISHI` | 修改召唤类型信息 |
| `CHANGE_SUMMON_LOCATION_KOISHI` | 修改召唤来源信息 |
| `LINK_SPELL_KOISHI` | 连接魔法规则 |
| `EFFECT_MAP_OF_HEAVEN` | 分支专用规则；没有 `_KOISHI` 后缀仍按专属处理 |

除最后一行外，表中符号均带 `EFFECT_` 前缀。界面标记这些常量并在上游目标禁用选择，导入的既有配置仍保留以供修正。编译和导出再次检查明确依赖、Lua 标识符和 `SetCode` 的直接数值；草稿导出也不能绕过。扫描使用 Lua 语法树，不把注释、字符串或普通卡号误判为扩展。

这属于已知能力的静态检查，不是沙箱或完整依赖证明：计算生成的代码、别名、间接加载的脚本及未收录的分支 API 仍需核查。上游增加对应功能后应更新来源和目录。不能把「没扫描出 Koishi 常量」视为通过全部上游兼容性测试。

## 仍需专门配置的情况

闭合文本匹配器仍只识别已有明确句式，不会因为手工工具箱扩大而声称任意卡文已被实现。未知部分继续保留并要求复核。

自定义素材替代规则、融合素材与前面步骤结果绑定、同时从额外卡组特殊召唤多只、特殊的接触素材支付或召唤类型、替代支付／替代破坏、任意事件历史与回合内誓约仍需高级回调或完整 Lua。延迟追踪目前针对准备／结束阶段，不能替代任意事件状态机。高级模式可以接入其他 API，但不会自动推断合法性或裁定。持续限制预设只在指定区域有效，不等同于「整个回合」的历史检查。
