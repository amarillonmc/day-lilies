# 萱草 · Day Lilies

面向游戏王 DIYer 的制卡工作台：管理一套卡片，上传中间图，匹配或手工组装常见效果，生成 Lua，并下载包含 CDB、完整卡图和脚本的 YGOPro 扩展包。

## 启动

需要 Node.js 22.12+ 和 npm。在本项目目录执行：

```powershell
npm ci
npm run dev
```

打开终端显示的本地地址（通常是 `http://127.0.0.1:5173`）。首次进入附有三张可导出的「昼庭」示例卡。点击左上角卡包名可以创建空白卡包。

启用官方卡片检索及 BYOK 参考上下文：

```powershell
npm run refs:sync
```

本次工作区已经准备了独立参考缓存。新机器需自行同步；手动积木、卡图和导出无需同步即可使用。正式部署使用 `npm run build` 和 `npm start`，详见[运行与部署](docs/deployment.md)。

## 使用流程

1. 新建卡片，或导入 MSE-SET、YGO Carder JSON、yugioh-card 作者制卡器 JSON。两种 JSON 使用独立适配器。MSE 的英文正文和中文注释分别保留。
2. 在「设置」里填写自己的卡号起点、系列名称与系列代码，给未编号卡片分配卡号。第三方制卡器中的密码字段不自动当作作者分配的卡号。
3. 填写卡面信息和中间图，在「效果积木」匹配卡文并核对；也可搜索模板、组合处理步骤或选择高级效果预设。整套卡可以批量匹配尚未配置的卡片。
4. 复杂效果可在「BYOK 助手」选择 OCG 参考卡，调用自己的 OpenAI 兼容模型；检查结果后应用为完整 Lua，也可手动编辑脚本和 CDB 提示。
5. 查看导出检查并下载 ZIP。将 `expansions` 的内容合并到本地 YGOPro / KoishiPro，在客户端试卡。

```text
expansions/
  卡包名称.cdb
  pics/卡号.png
  script/c卡号.lua
  strings.conf
export-report.json
README.txt
```

默认自动保存到浏览器 IndexedDB，可切换到本应用服务端。工程 JSON 备份包含继续编辑所需的内容；游玩用 ZIP 不替代工程备份。API Key 只保留在当前页面内存，不进入工程或导出包。

顶部或设置中的「界面语言」可选择中文、English、日本語，浏览器会记住选择。每张卡的「卡面语言」独立控制卡框、字体、种族和卡种标签；例如中文界面可以制作英文卡图。两种语言设置都不会翻译作者输入的卡名、卡文、备注或数据库内容。

## 当前能力与边界

- 33 个积木入口，支持融合／仪式召唤、基本分、无效、控制权、装备、表示形式、盖放、指示物及超量素材等处理；扩展事件、费用和筛选。
- 复合效果可在一次发动中组合最多 16 个步骤，包括融合／仪式召唤；配置多组独立对象、组间是否重叠，并引用指定对象组或较早步骤的实际结果；分别配置成功／失败条件、可选后续与处理时序。
- 普通特召／苏生支持同一次召唤最多 5 只怪兽，检查可用区域与召唤限制；后续步骤和延迟追踪可以引用实际召唤成功的怪兽。
- 可视化素材手续支持调整／非调整筛选、超量叠放路线、连接素材与融合素材槽；接触融合可配置素材来源、双方范围、支付方式与额外卡组召唤限制。融合／仪式召唤效果可选择素材区域、筛选及仪式等级规则。
- 延迟追踪可将某步实际处理的卡关联至指定准备／结束阶段，配置回手、回卡组、破坏、除外、送墓或暂时除外返回，以及失效和连锁规则。
- 高级效果提供 21 个可编辑预设、474 个脚本常量及 12 项 KoishiPRO 扩展的检索目录，并开放 Effect 参数与 Lua 回调；详见[扩展覆盖与边界](docs/effect-coverage.md)。
- 中英文封闭句式及少量日文匹配。未匹配内容明确显示，匹配结果必须复核。
- 整卡 Lua 编辑和 BYOK 生成，具有语法及入口检查。BYOK 是参考资料辅助生成，不是完整远程执行 scripting-workflow。
- 完整卡图含中英日字体、双灵摆刻度和连接箭头。依赖与必要资源都由本项目管理，运行时不访问其他工作区仓库。
- KoishiPRO 专属能力明确标识；上游 YGOPro 目标阻止导出检测到的专属效果，包括自定义 Lua 中的常量及直接填写的 SetCode 数值。动态构造的调用仍需作者核查。
- 不宣称无代码覆盖全部 OCGCORE：自定义素材替代规则、替代支付、任意事件历史、任意多分支以及特定裁定仍需高级回调或完整 Lua。实机测试使用 Koishi 内核，不代表所有上游客户端版本均已测试。
